
# 首先明确如下内容（请同步保持更新）：
1. 海量抓取商品有两种方式：搜索页抓取或店铺页抓取，这两种抓取不太容易被封，
    会更新commodity_info, shop_info, commodity_sales表,
    这两种抓取方式都不会更新商品详细信息（如offers和素材图），仅更新商品ID、标题、链接等基本信息；
 2. 指定商品，其销售信息的更新方式有一种：通过店铺页指定商品列表抓取，这种抓取也不太容易被封，
    会更新commodity_info, shop_info, commodity_sales表；
   不会更新商品详细信息（如offers和素材图），仅更新商品ID、标题、链接等基本信息；
3. 商品细节的抓取方式有一种：即商品页面抓取，这很容易被封，
   会更新commodity_info、shop_info，并可能附带更新commodity_sale表；
   这种抓取会更新商品的所有信息，包括基本信息（ID、标题、链接）和详细信息（如offers和素材图），
   可选的，这种抓取会下载所有商品页面素材到本地；
4. 为满足 #1、#2 和 #3 的要求，有三种手动抓取任务，分别为search_crawl_task, shop_crawl_task(可指定商品ID列表), detail_crawl_task,
   同时有一个自动抓取任务tb_crawler_task，它自动读取对应的task表并长时间自动运行；
5. 商品销售分析的基本思路如下：
   a. 基于数据库中的已抓取信息，某些商品的销售信息在当前时间点看没有更新价值，则什么也不做，这种商品等待搜索词抓取自动补充销售信息
   b. 若商品销售信息显示其有更新价值，视情况应保持一个最低的更新频率，若某商品的销售信息超时未更新，应建立shop_crawl_task任务；
   c. 有更新价值的商品的商品细节也应保持一个最低的更新频率，比如两周，我们每天更新一点，因为这很容易被封；
   d. 有更新价值的商铺也应保持一个最低的更新频率，比如一周，若商铺内容超时未更新，应建立shop_crawl_task任务；
   e. 满足某些特殊条件的商品，不但应被更新销售信息和商品信息，也应该抓取所有商品页面素材并存放于本地，便于之后分析和上架；
   f. 应调整策略使之可长时间自动分析运行而不触发淘宝的封号策略，因为抓取需要登录，这无法通过换IP绕过去

# 目前使用的策略如下（请同步保持更新）：
1. 最初的bootstrap：
   a.手动提供最初的搜索词，这里使用“网盘发货”，并按销量检索100页；
2. search_crawl_task 添加的具体策略：
   a. 手动提供最初的搜索词若干，这里使用“教程”、“影视”、“音乐”、“素材”、“自动发货”，并按销量各自检索10页；
   b. 同样的搜索词可以在不同时间反复运行，这同时是为了增加商品和销售信息；
3. shop_crawl_task 添加的具体策略：
   a. 可以手动提供目标商铺，调用程序添加任务到shop_crawl_task表，这同样是出于启发式的增加商品和销售信息的目的；
   b. 同样的店铺可以在不同时间反复抓取，这同时是为了增加商品和销售信息；
   c. 若基于现有数据，某商铺的基础年销售量超过10000元，且商铺内容一周内未更新，则添加任务到shop_crawl_task表；
4. detail_crawl_task 添加的具体策略：
   a. 若某商品的基础年销售额超过1000元，且商品信息一周内未被detail_crawl_task更新，则建立detail_crawl_task任务；
   b. 在商品详情页面被抓取的同时，下载页面素材到本地
